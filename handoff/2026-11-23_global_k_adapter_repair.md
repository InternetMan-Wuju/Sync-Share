## 3. A：任务身份放在计算数据之外

### 3.1 必须满足的合同

真实hidden的shape、dtype和全部数值保持不变：既不原地修改调用者张量，也不复制后偷偷改成另一份输入再计算。参考路径直接读取原始hidden，不调用adapter的输入预处理。

每个真实任务使用独立整数身份，例如 `(sender, token_index, topk_index, logical_expert, layer)`；通信编号另存。优先使用原生dispatch的实际排列/handle或让整数metadata严格跟随同一次排列；安装接口若不暴露所需信息，可加有限Python侧映射/metadata通信适配。

不能从hidden数值、浮点标签、权重是否为0反推身份；不能通过改变模型hidden维度或牺牲一个通道藏标签。不能另跑一次无关dispatch，再假定其排列就是被测那次的排列。若增加控制通信，记录其位置，留待未来计时纳入成本。

内部padding同样有独立身份，只由adapter生成，专家计算前剔除，combine后剥离。真实输入出现全零、相同hidden、数值200等，都不应变成padding。padding不申请专家状态，也不增加真实top8项数。

### 3.2 最小验证

1. 使用未打标签的合成hidden，保留小输入的q=0、部分、全部分流以及单侧空/双空用例。
2. 额外跑一次**两rank各259个token**的真实NPU用例，共518个token、4144个top8任务，使用部分分流。它同时跨过旧的16、200和BF16整数标签边界；不需要跑8192。
3. 输入中保留非零前两列，选少量合法值覆盖0、16、199、200、201、256、258，并包含两行数值完全相同但身份不同的token。预先记录种子、dtype转换后的真实值和路由。
4. 扩大dispatch容量到足够容纳259个输入及必要padding，记录实际配置；不能继续使用64上限后把失败归因于算法。
5. 同时检查调用者输入前后逐位不变，以及**真正进入专家量化前的每个真实hidden行**与其源token原始行逐位一致。仅比较调用者张量未改变是不够的；逐行审计可放在调试hook，不能修改被测数据。
6. 从实际收到的独立身份核对全组任务多重集、top8位置、输出回填、padding数量和真实专家调用。expected来自发送前计划，actual来自被测dispatch的真实接收/排列，不得把发送manifest复制成actual。不要仅验总数，不把固定字段`padding_expert_calls=0`当实测。

量化输出与独立参考用预先明确的误差定义和容差；所有路径记录绝对误差、约定相对误差、候选和参考非有限数量，并直接保存分流输出相对同入口q=0的误差。不要为了候选通过事后放宽阈值。输入保真本身是逐位检查，不受输出浮点容差影响。

若无法在不修改hidden的前提下获取同一次真实分发的身份，明确记录接口缺口；不要退回浮点标签却仍宣称修正完成。

## 4. B：owner核对真实槽，并固定它直到计算完成

### 4.1 修复方向

请求可以携带slot引用，但由owner核对真实池状态：池/会话身份、owner、local_slot、layer、expert、generation、ready，以及实际将使用的权重对象。不能只比较两个调用方字典，也不能让调用方把`ready=true`作为权威。核对须覆盖所有发送方本次使用的引用，不能只检查owner自己的参数；可汇总各方请求给owner核对，或广播已固定的真实身份让各方逐一比较，再汇总是否继续。

复用现有 `pool.use()` 的身份验证与使用计数：在dispatch之前核对请求并固定**被核对的那一代槽**，直到相关计算/通信设备完成后再解除引用。不要检查旧描述符后，在执行时改用一个未经绑定的“当前lease”。有任一rank拒绝时，所有rank都参加统一状态汇总、不dispatch；已经取得的引用在共同拒绝后正确解除。

只在本次确有真实任务去副本时要求槽。q=0和双空允许pool/slot根本不存在。预期校验失败不能让一rank提前抛错、另一rank卡在集合通信。这里处理本轮可预期错误，不实现任意HCCL故障恢复。

### 4.2 必须测真实状态变化，不能只改字典

| 用例 | 真正建立的状态与预期 |
| --- | --- |
| 没有副本，q=0 | 在任何install之前执行；目标无已安装槽，正常通过 |
| 真正未ready | 申请槽但保持RESERVED、未安装/未mark_ready；传入身份字段自洽、owner/slot/layer/expert/generation均对应预留lease、但声称ready=true的说明，必须因真实池未ready而双方在dispatch前拒绝；之后真实安装并ready，合法请求通过。不能用None或ready=false替代这个反例 |
| 换层后重放旧请求 | 装49层并保存引用；同槽换成50层；用49层旧引用请求49层，即使旧描述符内部自洽也必须拒绝；随后50层新引用通过 |
| 同层换代后重放 | 同一层释放/重新申请并安装，generation改变；旧引用必须拒绝，即使权重内容相同；新引用通过 |
| 仅一方信息错误 | 保留另一方正确状态，只让一rank持旧引用或非法comm128；两rank一致拒绝且实际dispatch增量均0，然后同进程合法用例通过 |
| 检查后尝试覆盖 | owner在持有本次使用引用期间，测试hook尝试释放/覆盖；必须被已有池规则拒绝或等待，不能覆盖正在使用的权重。避免让同线程等待自身造成测试死锁 |

generation检查用请求最初保存的真实引用，不通过同时修改“描述符”和“期望值”假造负例。记录owner实际状态快照与请求身份、拒绝原因、两rank真实dispatch调用计数。失败恢复后的正常执行要检查输出和任务守恒。

重新跑已有小矩阵，并补两类独立情况：“本rank没有输入、却接收另一rank任务”和“本rank有输入、却把全部任务发给另一rank”；不要把零发送与零接收始终绑定在同一卡。

修正后继续用同槽执行49→50→49三轮。由于前面真实负例也会申请/释放槽，**不要硬要求整个进程generation必须为1…7**：记录该段起始代际，核对7次安装层序列、真实代际递增、6次切换后输出和同一storage。若用独立新池开始该段，可预先声明从1开始。最终使用引用为0、租约归还；空闲池保留HBM与释放HBM区别记录。

父进程给每个新负例设置有限超时，建议初始化后60秒；如需调整，执行前记录。超时终止本轮子进程并标FAIL，不把超时当作成功拒绝。要求每个失败rank状态可定位，不能只留下“总脚本非零”。

## 5. C：比较真正不需要复制资源的基线

两个独立进程组使用同主库、同ND格式、同258入口、同输入/逻辑路由。这里叫**无副本资源对照**，不是正式原版性能基线。

| 资源/阶段 | B0无副本资源对照 | Candidate |
| --- | --- | --- |
| 原主专家、通信配置 | 相同 | 相同 |
| 目标pool与槽 | 不创建、不分配 | K=1 |
| 源flat及复制格式状态 | 不创建、不分配 | 实际需要多少记多少 |
| 首次合法执行 | q=0 | 安装后q=0 |
| 后续分流 | 无 | q>0，计算峰值单独报告 |

B0确实不执行复制，不能为让两边看起来对称而给它分配复制缓冲。Candidate即使q=0也保留已安装副本，用于观察静态资源成本；q>0工作量变化导致的临时空间另记，不混作槽本体。

在动作发生时取样：公共通信初始化后/主库前、主库就绪但副本资源创建前、flat/slot创建后、安装前后、相同q=0执行前后、候选分流前后、归还租约后、销毁缓冲后。必要设备工作完成后取当前allocated/reserved，不在运行末尾补写“after_bank”。

阶段峰值在阶段开始前重置，重置前保存此前峰值；维护所有阶段的全过程最大值，不丢掉构造/安装峰值。分别报告当前存活量、阶段峰值、全过程峰值。不同阶段最高值之差不是副本自身大小；跨rank峰值求和仅可标保守上界。

主库、slot、源flat、格式中间状态、整数metadata/padding、输入输出、通信/算子workspace、allocator缓存分别记账，无法归属的增量也列出。逐storage去重，指针只在同一进程内用于身份比较。实际format code、stride、alias从运行对象读取，不固定写成ND或共享存储。

参考输出计算和完整正确性审计放在功能进程，避免它们污染显存进程峰值；显存进程仍保留轻量正确性检查及已知输入身份，明确自己的范围。必要时参考单独运行并释放其验证专用对象，不能把参考临时空间写成线上必需成本。

预期旧格式下槽约37,810,176 bytes，源flat也约同大小；以实测为准，不把两者合称两个可调度副本。报告必须能回答“目标槽多少、源搬运缓冲多少、其他实际开销多少”，而不只是rank1的差值。

## 6. D：验收器要拒绝不一致和过期记录

一次 `all` 生成新的campaign UUID及独立输出目录；functional、memory-baseline、memory-candidate各有subrun UUID。启动器先写预期任务清单，各rank/安装/阶段记录携带campaign、subrun、代码哈希、rank和用例/阶段身份。

validator使用命令行显式传入的expected campaign和启动清单核对，不能从第一份结果猜“本轮是谁”。分阶段执行必须显式指定所属campaign或创建新campaign并标未完成阶段；不能自动读取旧文件补成PASS。保留服务器大张量时附路径/哈希，并区分仓库可核验文件与服务器保留文件。

从原始误差、有限值计数、任务实际/期望身份、owner状态、真实格式与storage清单重新推导各阶段结果，不只读取`case_pass/within_tolerance`。检查两个rank的数量、次序和最终状态；验证每条复用记录，不用`zip`静默截断或`all([])`判通过。容差定义、格式范围和未测项要与代码一致。

对**内存拷贝fixture**做最小反例回归，正常证据应通过，以下每类定点改坏必须失败并给原因：

1. 任一rank的campaign/subrun/代码哈希过期或缺失；缺rank、重复case、缺安装、阶段乱序。
2. 输入前后不一致，或实际专家输入与源token不一致，即使`case_pass=true`。
3. 请求说明自洽但owner真实layer/generation/ready失配；负例记录dispatch非0。
4. 实际误差超限、出现非有限值、任务多重集不一致、复用status失败，即使先写好的容差布尔值为true。
5. format查询ERROR、违反本次声明格式、槽view不再共享槽存储、源目标hash不一致。
6. B0出现flat/slot/复制格式缓冲、Candidate出现第二份可执行持久副本、复用storage更换或代际不递增、缺最终释放。

上述回归不改实际原始记录。它们验证审阅工具能发现错误，不能替代真实NPU用例。
