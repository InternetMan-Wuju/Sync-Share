# Prefill K=1：原生分发可行性与已有副本路径诊断

日期：2026-11-22。审阅基线：`d0c4a3f482bd96471b01daf76b104e4b21c3b5ac`。

本轮回答两个问题：**原有 token 分发/结果合并流程能否接入全组唯一副本？副本已经准备好时，当前路径的额外时间究竟花在哪里？** 不预设原生接入一定省通信，也不以找到正收益作为交付条件。

用户已授权服务器按本方案实施和验证。保留旧实验，使用独立目录及可关闭补丁；普通实现选择自行处理。总预算以 **3 小时为上限**，到点停止新实验，安全收尾并交付已有证据。

## 1. 从上轮得到的可靠结论

[上轮报告](../shared/current_exp/20261122_global_k_breakeven/REPORT_FOR_REVIEW.md)和原始计时已经复核：

- 324 次执行 = 108 个三模式配对组。输出与同一手工专家链参考一致；不是完整 MoE 层正确性证明。
- 临时复制 108/108 组变慢。已有副本仅 9/108 组变快，所有测试点的逐对收益中位数均未转正。
- 最接近点 `n=8192,q=2048`：原路径中位数 2.2149 ms，已有副本 2.2493 ms，逐对收益中位数 −0.0383 ms。
- 该点 5 个正收益组中，4 个发生在原路径排第一时；原路径排第一总共也只有 4 组。原因尚未确定，不能直接叫缓存问题。
- 当前 `existing` 每次计时前重新安装，调用结束归还槽；尚未验证持续驻留。目标侧每次重新建立权重视图和专家链对象。
- 上轮重叠证据使用主机时间包围提交和设备同步，不能证明两卡计算核实际并行。
- 旧自然路由只保留四个 step 共约 4066 个 expert43 任务。不能把这个累计值当作单次调用收到 4096 个任务。

CPU 的 q=4 漏解、同分不复制、释放竞争已有修正，24 项本地回归通过。但找交点仍枚举 `q=1..n`，人工案例搜索中位数约 0.54–85.8 ms；本轮继续手工给配额，不接自动规划器、不增加搜索算法研究支线。

- 沿用两张空闲 Ascend 910C、原镜像和真实 GLM layer49 / expert43、ModelSlim W8A8；启动前核实实际版本、空闲设备和内存。设备忙则报告，不终止他人任务。
- **全 EP 组 K=1**，固定副本 owner；跨层共用原则不变。本轮只用一个层验证，不增加逐层权重缓存。
- 固定主点 `n=8192,q=2048`，复核点 `n=4096,q=1024`；n 是该专家收到的任务数，不是提示词长度。
- 不做 Decode、K=2、跨节点、多请求并发、全模型服务、TTFT 或新一轮冷复制矩阵。不扩大 n 或搜索 q 追求正结果。
- A 接口核查约 45 分钟；B 设备诊断和热态对照约 60 分钟；C 条件式最小接入约 60 分钟；最后 15 分钟整理和推送。某阶段阻塞后完成独立可做部分，不把剩余时间用来扩大实验。

## 3. A：先查清真正的数据路径和接口合同

用三个名字，避免把“源卡”混为一谈：

| 名称 | 含义 |
| --- | --- |
| S：原发送卡 | token 在本层分发之前所在的卡，也是该 token 结果最终应回到的位置 |
| P：原专家卡 | 原版布局中保存该逻辑专家权重的卡 |
| D：副本卡 | 保存额外槽、执行分流任务的卡 |

**当前两卡实验是 S=P=rank0，D=rank1。直接送副本仍是 S→D→S，不能声称省掉这一次来回。** 只有真实路径原本存在 S→P→D→P→S，提前改派才有机会删除中间两段。本轮两卡不用于证明三卡或跨节点场景的通信收益。

先从安装中的真实源码和实际命中分支核查，不凭接口名推断。历史入口仅用于定位：

- `sglang/srt/models/glm4_moe.py` 的 MoE forward；
- `sglang/srt/hardware_backend/npu/moe/topk.py`、逻辑/物理专家映射；
- `sglang/srt/layers/moe/token_dispatcher/deepep.py` 和实际导入的 `deep_ep` / NPU 扩展；
- `sglang/srt/layers/moe/moe_runner/ascend.py`、`hardware_backend/npu/moe/matmul.py`；
- `sglang/srt/hardware_backend/npu/quantization/moe_methods.py`、`eplb/expert_location.py`。

记录真实文件位置、版本/哈希、命中的 Prefill 后端、分发与合并参数、专家编号如何变成 owner/local-id、分发结果如何进入 GMM。旧镜像文件和参数不代表当前环境。低延迟后端的参数不能未经验证套用到 Prefill。

必须给出下面五项的“支持 / 需小适配 / 当前不支持 / 未证实”，并附源码位置或最小调用证据：

1. **非等长额外容量。** 256 个逻辑专家加一个物理副本是 257 个实例；两卡简单布局为 128/129。实际映射可以不同，但不能暗中改成两卡各一个备用槽。
2. **保持逻辑路由不变。** expert43 的部分任务改到其副本，不改变 top-8、权重或增加第九个逻辑专家。
3. **外部槽执行。** GMM 能否从现有槽视图读权重，还是强制要求所有权重处于规则连续 bank；不能每次复制整层权重来伪装接入。
4. **正确返回。** 原 token 位置、top-k 位置、发送 rank 和合并权重如何保持；任务只完成一次，路由权重只乘一次。
5. **所有 rank 协议一致。** 没有槽或没有任务的 rank 仍正确参加必要通信；ready、版本失配及失败分支不会导致一侧等待另一侧永不调用的集合通信。

如果只需元数据 padding，允许验证，但必须证明填充位置不会被派任务、不会额外分配完整专家权重。若后端要求每 rank 实体冗余槽、必须重写设备通信内核或必须扩卡，停止本轮原生接入，保留精确阻塞证据。不要把自写 P2P 路径重新命名为“原生分发”。

## 4. B：固定两个点，查设备等待和运行顺序

### B1. 短设备时间线

在主点 `8192/2048`，原路径和已有副本各采最多两个预热后的短窗口。使用当前环境可用的 msprof / torch_npu profiler 或等价设备记录，明确区分：

- CPU 准备、权重视图/链构建；
- token 发送与接收；
- 两卡量化、两次 GMM、激活算子；
- 结果返回与回填；
- 控制握手、槽使用/归还、stream 等待及设备空闲。

记录真实设备任务起止、stream 和依赖。跨设备时钟未确认对齐，就只解释各卡内部依赖，不给“计算重叠百分比”。不能把包含等待的主机时间窗或 HCCL 接口耗时称为纯计算/纯传输时间。

如果 profiler 不可用，记录错误及缺失证据，继续正式计时；不要另造主机窗口冒充设备证据。诊断数据不进入性能样本，阶段有重叠时不能简单相加。

### B2. 明确区分旧条件和“持续驻留”新条件

先在主点按上轮语义做 **12 对原路径/已有副本**，保留每次安装和归还，用于核查顺序效应。这不是重跑整个旧矩阵。此组及下述可选准备敏感性诊断均各用两个种子，每种子 3 对原路径先、3 对分流先，以固定随机种子打散，分别报告两种顺序的结果。

然后验证一个明确的新条件：**同一份副本在一个测量块内持续 ready**。

1. 测量块开始前安装一次，核对层、专家、权重版本、量化和槽 generation；构建可复用的权重视图/专家链，必须仍引用这唯一槽的存储。
2. 原路径和分流路径都面对同一份已驻留副本、相同分配/预热状态。原路径不使用副本，正常完成全部 n 个任务。
3. 分流调用通过 `use` 或等价使用引用读取槽；本次输出和远端工作完成，且本次使用引用已安全归还后，才结束计时。驻留租约及槽内容保持 ready，测量块结束才逐出。不能绕过正在读权重时不可覆盖的保护。
4. 单独计完整安装时间、字节数、对象准备和最终逐出时间。变化是“持续驻留及对象复用”，不能说只是修正计时，也不能把它与上轮每次归还的数字混在一列。
5. 这一条件只证明同一专家连续调用时的有条件成本。**不证明实际多层模型会命中，也不能预支未来请求收益。** 全组 K=1 被其他层使用时，当前副本仍可能被覆盖。

如果池无法在现有安全协议下保持 ready，本轮不要改造通用缓存管理器。保留旧语义，增加主点 12 对“两个模式前均做相同计时外安装”的准备敏感性诊断；将原路径明确标为“安装后原路径”，不替代原始基线，不把人为增加的原路径准备/归还算作加速收益。报告驻留条件未完成。

### B3. 正式对照协议

对已通过正确性的持续驻留条件，在两个固定点各做 **两个独立进程轮次，每轮 12 对**，共 96 次正式执行。每轮两个输入种子，每个种子包含 3 对原路径先、3 对分流先；平衡后用固定随机种子打散顺序，保留顺序表。

- 预先生成输入、指纹和参考输出，避免每对开始只先运行一次完整原路径。两种模式及 full/main/external 形状都充分预热，记录次数和流程。
- 同步只能保证任务完成，不能声称恢复相同硬件缓存。无需人为清缓存或添加长等待；通过统一驻留条件、均衡顺序和分层统计观察影响。
- 计时开始于公共入口：相同 token、路由和手工配额已经可用，尚未执行本次分发；结束于相同位置的完整输出可消费，远端本次工作完成且本次使用引用安全结束。
- 所有本次实际执行的准备、通信、回填、必要同步和槽使用管理都计入。不开详细 profiler，不加逐段全设备同步，不人工减去控制成本。
- 相同输入、相同输出位置、相同正确性检查策略。记录实际任务 ID 和去向，不能只检查 `n−q+q=n`。当前连续切片子链检查无重复无遗漏；原生路径另按 top-k 身份检查。
- 保留所有样本，按轮次、原路径先/分流先分别报告逐对收益中位数、范围、均值和变慢次数。正确性先按上轮 max_abs=0 检查；误差出现就定位，不事后放宽条件。

只有两个独立轮次均正收益、两个顺序分组也均为正，且每轮 12/12 对为正，才称“该驻留条件下稳定回本”；这只是本轮操作性标准，不是统计置信保证。混合正负则如实说不稳定。无需因此追加第三轮或改 q。

原安装/释放语义、持续驻留语义、准备敏感性诊断分别出表。对比前后时列明变化，不把更改生命周期边界后的差值全部叫测量误差。

## 5. C：接口允许时，做最小原生闭环；否则交付阻塞点

仅在 A 找到保留真实 K=1 的可行路径、B 完成必要安全检查且预算尚有余量时执行。优先用小型隔离 harness，不启动完整模型服务。

### C1. 先验证实际分发/合并接口和任务身份

使用真实 **256 逻辑专家 / top-8 / 两 rank / 全组额外 K=1** 的元数据合同；可以只用少量 token 和可识别测试值，不必为元数据检查加载全部专家权重。

任务身份为 `(请求/批次, 原发送rank, token位置, top-k位置, 层, 逻辑专家)`。设置来自两张卡的任务、零任务专家、同一专家部分分流和零分流；核对分发到正确 owner/local-id、副本确实执行选中的任务、原位置回填正确、没有重复/遗漏/多乘路由权重。

可以用确定性标记计算验证合并，但必须称“分发/合并协议验证”，不能称真实 GLM 输出。仅 top-1 或缩小专家数的成功只算接口冒烟，不能替代上述合同验证。无法表达 257 个实例时，在具体限制处停止，不偷偷改 K 或覆盖主专家。

### C2. 条件式真实专家计算

在 C1 通过后，尝试将实际 expert43 的任务送入唯一外部槽，执行真实完整 W8A8 专家链，再沿原生合并元数据返回。其他逻辑专家的工作与基线必须一致；若只回放受影响专家，明确标记子链范围。

先验证 `q=0`、部分分流、目标无任务三种情况；逻辑 top-k 和权重保持原样。compare 的参考路径与候选应有独立任务索引核对；同一手工链数值一致仍不等于原生完整 MoE 独立对照。

**性能测试是条件扩展，不是强制成功项。** 只有真实计算正确，且原生基线、原有分流路径、原生分流路径能够共享相同输入归属、相同任务和相同完整输出终点时，才在主点 `8192/2048` 做最多 12 个三模式配对组；三种模式全部 6 种顺序各两组。

三者都采用一致的已驻留副本条件，开始于分发前，结束于合并输出可消费；原生调用的映射、重排、dispatch/combine 和安全依赖均计入。不能拿“已收到 token 后的旧计时”与“分发之前的原生计时”相减，不能用省略其他工作/占位计算的结果声称全层提速。若公共边界无法对齐，仅交付正确性，不报告加速。

本轮原生性能只作为探索结果，不因几次变快再追加规模或宣布完整 Prefill 提速；正式确认留待下一轮。

## 6. 本轮的决策和停止条件

| 证据 | 本轮结论与后续方向 |
| --- | --- |
| 原生接口无法保持 K=1 | 给出精确的专家布局/外部权重限制和所需改造；不擅自改成每卡冗余 |
| 驻留条件仍亏，设备时间线显示通信或等待占据关键路径 | 给出占据关键路径的具体设备操作/依赖；下轮针对它验证一项改动，不继续调门槛 |
| 驻留条件稳定赚，旧语义亏 | 有条件的驻留复用有价值；下一步需证明真实命中机会，并计首次安装和跨层驱逐 |
| 仍只有某种运行顺序赚钱 | 准备/运行状态影响尚未排除，不能宣布稳定收益 |
| 原生接口和真实子链通过 | 原生接入可行；收益仍按本轮公平边界单列，完整 MoE/TTFT 未测 |
| 时间或工具不足 | 交付已完成证据和具体阻塞；不自动扩卡、扩时或继续下一轮 |

不以这次的负结果证明“所有在线复制无效”，也不以驻留条件的正结果证明“首次复制已经回本”。自动规划成本、完整模型效果与自然复用命中均仍未验证。
