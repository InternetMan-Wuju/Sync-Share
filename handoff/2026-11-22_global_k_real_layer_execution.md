## 2. 本轮不能改变的约束

1. 全 EP 组总共 K 个真实额外 routed-expert 槽，跨层复用；不是每 rank K 个，不要求 K 是 EP 的倍数。
2. 第一版固定 owner。只有 owner 分配对应槽；冷卡没有槽就不能免费接收副本。动态移动槽落点不作为本轮前置。
3. K 限制同时存在的槽容量，不限制跨层累计装载次数。临时格式转换、收发缓冲、分配器缓存单列真实预算，不隐藏另一份逐层权重池。
4. token 分流只改变执行该任务的物理副本，不改变逻辑专家、router 的 top-k 和合并权重。一项任务以“输入 token 位置＋top-k 位置＋层”标识。
5. 先手工确定配额验证执行正确，再接门槛与筛选。自动版本每次使用当前 routing，允许零个、一个或多个动作。
6. 当前串行复制按完整成本计费，未验证的重叠或未来请求收益不能预支。
7. 本轮聚焦 Prefill。32 卡全模型启动、完整 TTFT 四档、Decode 和动态槽迁移属于后续任务，不阻塞本轮最小验证。

## 3. A：先补正确性接口，同时完善 CPU 算法模型

### A1. 槽接口必须明确的事情

审阅发现：

- [GlobalSlotPool](../shared/current_exp/20261116_global_k_online/scripts/global_slot_pool.py) 在一个进程里为全部逻辑 owner 建池，allocator 没有 owner 参数。单设备 `[2,2,5]` 的槽实际都在 npu0；多卡 probe 则是各 owner 独立建一个池。不能在真实服务每个 rank 都按完整 owners 列表分配一遍。
- `GlobalLease` 缺池身份，`_local()` 使用被调用池的身份重建局部租约。不同池的相同 owner/slot/generation/request 组合可以误接受外来租约。
- 局部 `SlotPool` 有 `abort`，全局 wrapper 未暴露完整的失败取消路径。
- [SlotPool.use](../shared/current_exp/20261116_global_k_online/scripts/slot_pool.py) 只追踪 Python `with`，不会自行等待 NPU 读权重结束。当前 probe 显式同步，不能删除同步后直接宣称并发安全。

最小处理：固定一份 EP owner 布局，各 rank 只分配自己的槽；执行计划中包含槽身份、版本、目标层/专家及量化分片信息。明确复制完成后才能发布 ready、读取完成后才能复用、失败时不能发布半成品。

复制或安装失败后，必须确认相关设备写入和通信已经结束或被安全隔离，再释放槽。CPU 异常退出不等于没有在途写入，不能让失败任务继续覆盖下一份租约的数据。

第一版允许用明确同步保证安全，但同步开销必须计入。之后若改成设备事件等待，要重新验证，不能把 CPU 返回当作设备完成。无需先建设复杂的通用分布式槽管理服务。

验收至少覆盖：外来池租约、旧 generation、未 ready 读取、设备仍在读时覆盖、安装失败回收、不同层同编号专家。多 rank 时汇总每张卡实际槽容量和字节数，不仅由 rank0 打印常数 K。

### A2. 把 CPU 模型改成真实合法动作

[toy_global_search.py](../shared/current_exp/20261116_global_k_online/scripts/toy_global_search.py) 当前 Action 没有专家身份，q 上限是整张源卡的总量；`Slot.expert` 没参与判断，仅用 ready 判定免费复用。这份 toy 可保留作搜索思想示例，不能直接接模型。

最小新状态：逐层逐专家的任务数和原始位置；槽的 owner、内容身份、空闲/准备/使用状态；候选动作的专家、目标槽、整数配额和是否需要复制。

必须满足：

- 每个专家原位置处理数＋各副本处理数＝该专家当前总任务数。
- 一个槽只能处理其实际权重对应的专家；层、专家、版本或分片不匹配时需要重新准备。
- 正在使用的槽不能覆盖；复制后最终配额为零的动作取消。
- 完整方案无净收益时返回“不动”；不能因为 token 更平均就在等收益时复制。
- 多动作组合可以经过暂时亏损的中间状态，不用第一、第二慢卡之差拒绝整个组合。

用 2～4 rank、少量专家、K=1/2 和小整数配额枚举所有合法方案，另设完全旁路基线。对照有限搜索，报告不合法方案数、漏掉盈利方案数、最差目标差距、规划 CPU p50/p95。将“候选配额没包含好解”和“搜索剪枝丢掉好解”分开。

反例必须包含：双忙卡 `[40,39,1,1]`；卡总任务数相同但专家组成不同；错误专家的 ready 副本；冷卡无槽；忙槽；过量分流；零收益；已有正确副本免复制。

新 gate 也尚未实现。可以研究 `U = B0 - L` 的乐观收益初筛，但要写出工作量和成本假设；找不到可信成本下界时放宽初筛，不能用平均复制成本冒充严格下界。已有副本分流与新复制分别处理。最后由完整方案收益条件决定执行。

## 4. B：单卡、真实专家、K=1，先证明算对

只加载目标层需要的专家或从已有正确 runtime 导出完整状态即可，不要求先加载整个模型。优先沿用实际 layer49，若当前模型配置不同则记录所选层及原因。

使用真实权重、真实量化参数与实际格式，覆盖：第一组矩阵计算 → 激活 → 实际中间量化 → 第二组矩阵计算。不能只用全 1 scale 或 64×64 随机矩阵替代。

对同一组输入分别运行原 bank 与池内权重，手工取不分流、部分分流、全部分流及零 token 等情况，验证输出和任务回填。输入优先来自真实运行捕获的激活及 routing；若只能用合成激活，明确标注，不能声称已覆盖真实数据分布。

接法先做小范围选择：

- 主权重＋外部槽的多 tensor GMM；
- 主路径与副本独立完整专家链，再按原位置回填。

先选择最容易证明正确的一条走通。若第一条受格式或接口阻塞，验证第二条；不要在两条上同时大改。独立副本路径在同卡串行执行的额外启动和计算开销须计入。

验收：

1. 实际权重和附属量化状态清单、数据来源、格式与字节数可追溯。
2. 完整专家链数值对照通过；误差容忍依据预先说明，不为通过而事后放宽。
3. 池内权重直接参与计算，无隐含的逐层永久备用 bank。
4. 没有任务重复或遗漏，合并权重和原位置正确。
5. 记录真实额外显存，单卡结果只证明正确性与局部开销，不称为跨卡均衡加速。

## 5. C：两卡单层、K=1，完成真实复制与分流

源卡保留原专家；只有目的卡有一个额外槽。复制实际完整 expert state，不能继续用 1024 B payload 作为成本结果。以 runtime 实际字节数为准，不硬编码历史 37.8 MB。

同一份输入、routing、配额，依次验证：

1. 原路径：任务全部由原布局处理。
2. 冷副本：复制＋格式准备＋ready＋任务分流＋完整专家计算＋回填。
3. 已有正确副本：核对身份后直接分流，仍计控制、通信和回填。

明确原路径减去哪些 token-expert 任务，副本接到哪些任务。优先保留目的卡原有的其他专家工作；若只回放专家子集，报告明确写“子链回放”，不能冒充完整层或服务。

用统一起止边界计时，等待参与设备真正完成；分段计时用于解释总时间，不能把几次独立测得的最慢耗时拼成“端到端实测”。保留各 rank 时间、所有额外通信与同步成本。单卡拷贝时间不能替代跨卡 HCCL 时间。

数值与任务守恒先通过，再计时。计时至少有预热和重复原始记录；可从 10 组成对对照起步，交替顺序，区分冷副本、已有副本和 allocator 状态。若波动与差值同量级，报告尚无法分辨，不宣称加速。不同输入覆盖留在后续扩展，不靠单个胜例概括泛化。

## 6. D：两个真实层复用，再接自动算法

先让两个不同真实层轮流借用同一个槽，往返多次。核对层/专家身份、设备完成时机、失败回收，以及 allocated/reserved/峰值是否逐次累积。仅更改 layer_id 并写字节不算真实跨层计算验证。

随后把手工计划替换为通过 A2 的 gate＋筛选。成本记录来自 B/C 的实际计算、复制、准备与通信；可做有限启动标定，并用低开销计时更新。每次仍根据当前 routing 决策，不固定照搬 6.415ms、0.5ms 或搜索宽度。

评价完整方法时，统计、汇总、规划、准备、通信、计算、回填均计入。临门比较执行和回退时，只算后续成本，避免重复扣除已支付的搜索费用。

有可用资源且前面通过后，在至少 4 rank、K=2 的配置验证两个源卡共同减负；这是本轮扩展项。固定 K 小于 EP，并保留无槽 rank，检查空任务分支与所有 rank 的协议一致性。手工与自动计划使用相同输入及初始槽内容，不能因缓存不同制造收益。

## 7. 32 卡与完整服务的处理

32 卡可作为独立环境准备项，但不阻塞 A～D。仓库已有 v0.5.19、TP32/EP32、DeepEP normal 在 MTP 开关两种情况下出现 `aclnnNotifyDispatch` 错误的[历史记录](../shared/history_exp/08_MTP推测解码续_2026-10-11/Q1MTPExp/MTP配置排列组合与AboutModels对照_20261012.md)。这不是当前版本必然失败的证明，也不是可以忽略的前提。

先核实空闲设备、实际 HBM 及当前目标镜像支持，再决定完整服务使用 16 卡还是 32 卡。EP16→EP32 的 routed expert 数变化不等于整卡所有内存减半；需分别核算 attention/dense/shared、KV、通信和临时缓冲。两卡单层实验不需要完整模型能装进两张卡。

完整层接通后，后续顺序保留：多输入单层 → 单输入多层 → 多输入多层 → 关闭详细 profiler 后测完整服务 TTFT/吞吐，并保留 TPOT 观察。四档 EPLB 对比必须确认相应动作真的发生，不能把未重排或未复制的结果当成功能效果。
