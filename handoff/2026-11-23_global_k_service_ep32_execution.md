## 1. 现有证据与本轮交付

EP16 的 layer49 回放使用 272 个通信编号和一个 37,810,176 B 的真实槽。三个长短档确实有任务走副本，保存的数值误差为零。上轮服务失败的命令只传了原生 `--ep-num-redundant-experts 1`，在 `257 % 16` 处被拒绝。服务仍缺把回放里的通信编号和实存分开的接线。原生 EPLB 静态布局可启动，但在线更新遇到内部格式 storage offset 和显存不足。上轮用的是 ShareGPT。保留旧结果作为接线和故障证据。[上轮报告](../shared/current_exp/20261123_prefill_eplb_three_way/REPORT_FOR_REVIEW.md)

本轮要交付可在真实 SGLang 服务启动时配置的全组 K 槽，以及**两台机器的全部 32 个 die、同一个 EP32 组、AgentX 8192/16384/32768 输入 token 的三组对照**。小规模用少量 die 验证，完整对照在 EP32 完成。优先实现最小可靠路径，手工计划即可验收真实装槽、分流、计算、合并和跨层复用。

## 3. 把我们的方法接入真实服务

### 3.1 配置与布局

- K 是一个 EP 组跨层共享的真实额外槽总数。启动时从一份统一配置读入 K 和各槽 owner。检查所有 rank 一致，且各 owner 的槽数之和等于 K。固定 owner 足以做第一版。同一份可执行代码至少用 `K=1` 与 `K=2` 启动，关闭路径或 `K=0` 要通过原版输出对照。
- 保持模型每层 256 个逻辑专家和原始主专家存储。我方使用自己的 K 配置，原生冗余参数保持 0。将逻辑专家编号、DeepEP 通信编号和实际权重位置分别表示。原生 dispatcher 如需等宽编号，可按「每 rank 主专家数 + 单个 owner 的最大槽数」设置通信区间。例如 EP32 每 rank 有 8 个主专家，各 owner 最多一个额外槽时，可用 288 个通信编号。其中只有已配置的 K 个额外编号指向真实外部槽，其余由协议处理。核对加载器、量化和计算实际只分配主权重及 K 个槽，给出实际张量和存储清单。
- 在目标镜像实测通信 id、每 rank 编号范围、接收分组与返回排列。占位编号只能按协议处理显式 padding，真实任务发给占位编号时应在 dispatch 前共同拒绝或回退。正负例均需证明各 rank 的决定一致。

### 3.2 真实请求走完装槽到合并

- 保留 router 的 logical top-k 和权重。根据真实 router 输出和固定配额构造物理改道，保证每个被搬走的任务只在副本算一次，原位置和 top-k 合并权重保持一致。主专家用现有 grouped 计算，外部槽可先用独立的真实 W8A8 专家链，结果回填到本次 dispatch 的接收顺序，再沿同一份 metadata 走 combine。核对 shared expert 正常执行。
- 以 owner 的真实记录核对 slot 身份、层、专家、generation、状态和实际绑定的存储。确认复制完成才发布 ready，持有对应租约直到设备使用完毕。跨层重装同一槽要证明存储复用、代际变化且旧引用被拒绝。若使用多个 owner 或多并发调用，验证租约绑定与释放语义。首轮请求可串行，按实际验证范围报告。
- 先用少量 die 跑真实框架入口的关闭/开启对照。覆盖 q=0、固定配额 q>0、K=1、K=2 两槽同时接收任务、至少两层接入且同槽跨层复用。扩到 EP32 后，在真实服务请求中记录至少一次非零改道、对应层和 slot，以及跨节点 activation 或权重传输证据。K=2 的小规模正例用于确认实现可配置，EP32 主对照选定并记录 K。
- 用相同输入比对 MoE 层的实际结果，提供任务身份、权重、多重集、有限值与误差。容差先由原版重复运行或参考路径确定，按实际精度报告。服务另核对请求成功完成、有效 prompt token、涉及层和真实副本任务。可先从 layer49 接入，再扩到另一层验证同槽复用，报告已启用的具体层。

## 4. 正式 EP32 三组

| 方案 | 全量执行方式 |
|---|---|
| 原版 | 原生 SGLang 和 DeepEP，原布局，EPLB 关闭，零冗余专家。 |
| 原始 EPLB + 冗余 | 使用目标镜像的原生算法、映射和更新器。EP32 起始配置为全组每层 +32 个真实冗余位置，以实际版本核实。独立校准窗口产生布局，确认在线重排完整结束、权重与映射生效，再运行保留输入。 |
| 我们的全组 K 槽 | 使用本轮服务适配，记录 K、owner 分布、真实槽数与分配字节、安装和实际分流任务。可以用固定配额验证功能，保留 q=0 诊断。 |

原生 EPLB 的重排做单独探针。先查看内部格式张量、更新器使用的切片及 storage offset，分开核对格式问题和临时峰值。EP32 上从小负载尝试，记录 start/end、实际前后布局和受影响的 rank。若原生在线更新仍受阻，按故障归类，继续完成其它组。加载原生策略静态布局所得数据可以作为诊断单列。兼容性修正若有必要，单独记录补丁、原版与修正版口径，保留原生策略。EPLB 计数区分「有多个副本的逻辑专家的总任务」与「实际落到额外位置的任务」，同时保存物理位置计数。
