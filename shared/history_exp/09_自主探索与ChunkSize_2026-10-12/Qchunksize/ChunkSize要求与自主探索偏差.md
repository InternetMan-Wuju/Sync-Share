# ChunkSize要求与自主探索偏差

更新时间：2026-10-13T14:09:19。只核对本次自主探索。

**W1要求客户端并发32、正式请求64。自主探索只跑了并发2/4，未完成W1规定并发的ChunkSize对照。**

| 项目 | AboutModels W1基线/当前要求 | 自主探索实际 |
|---|---|---|
| 客户端并发 | 32 | 2、4 |
| 正式请求数 | 64，即2×并发 | 4、8 |
| 并行布局 | TP16 / DP2 / EP1 | TP16 / DP1 / EP16 |
| DP attention / LM head | 开 | 关 |
| DeepEP | 关 | auto，开启 |
| Chunk基线 | 8192 | 扫描1024/4096/8192/16384，用16384作表内比较基线 |

当时因KV容量和服务启动限制选择了小并发预实验，随后止步于该网格。没有实际测并发32，不得把容量估算或其他配置的启动失败写成并发32无法运行的证据。

客户端并发、服务器running batch和KV驻留量是不同指标。客户端发出32个请求时，服务器可以只处理其中一部分，其余排队；排队时间应计入TTFT。文档W1同时列Concurrency=32与Running Batch=14，正说明二者不能混为一个数。

现有34单元是低并发预实验：20个基础单元及14个复测。它们可描述已测配置、已测并发下的Chunk差异，不能替代并发32结果，也不能据此为W1榜单宣布4K/8K最优。

后续W1正式对照应固定并发32、64请求和一套明确的基线配置，再只改ChunkSize。W1榜单的NoEP基线与通用默认脚本也要区分；DP/EP/DeepEP等同时改变时，不能把总收益归给ChunkSize。
