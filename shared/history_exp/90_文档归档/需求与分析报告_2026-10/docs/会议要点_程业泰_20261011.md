## 2. MTP（MTP.md 给出的硬指标）

- 固定配置 **MTP = 3**（3 个 draft + 1 个 bonus，所以接受长度上限约 4）
- 用例：
  - 用例 1：总输入 100K / 输出 1K / 缓存命中 90%（用户后续已确认；共享部分约90K）
  - 用例 2：前缀 32K / 输出 300 / 缓存命中 60%
- 精度：KVV 误差 ≤ 3% ⚠️待确认 KVV 指什么；AL ≈ 2.0（±5%）
- 延迟：P50 TPOT < 33ms；P50 TTFT < 15s
- 目标：两个场景下**最大化吞吐**
- 参考基线：线上实测 AL 高点 2.11、低点接近 0
- 若后续要做非 3 的 MTP，按 per-position 接受率 0.498 / 0.345 / 0.267 来配
  （MTP.md 另给了一组 0.148 / 0.093 / 0.056，⚠️对应哪个用例待确认）

**会上对 MTP 的批评（重要）**：
- 你报的接受长度 2.77–4.00 被游兴业质疑"等于全接受了"，老板也说不理解为什么接受长度能到 3 点多。
- 现场报告的现象：部分随机输入输出少数token循环，接受长度接近4；这需要检查输入、权重、结束条件及实现。后续实测表明典型循环的接受计数是真实的，且该循环没有EOS，不能把`ignore_eos`视为所有循环的必要原因。
- 字幕明确说**随机数据集可以用**。后续需要对齐输入构造与条件，区分固定长度压力测试和真实业务解释；不把循环压测接受率直接当作业务接受率。
