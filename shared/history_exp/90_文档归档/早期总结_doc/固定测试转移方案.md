# 固定测试迁移方案

目标：用我们现有的 SGLang 部署和压测脚本，复刻 `doc/固定测试.md` 里 4 个参考测试的 workload，得到可横向对比的 tokens/s、TPOT、TTFT 等指标。

## 0. 我们现有的能力（基线）

- 部署：SGLang 统一服务（非 PD 分离），`TP=EP`，`--moe-a2a-backend deepep --deepep-mode low_latency`，`context-length 131072`。
- 硬件：4 机 × 16 chip（Ascend 910C），共 64 chip。
- 模型：GLM-5.2 W8A8（`/mnt/raid/user/data/models/glm-q`）。
- 压测：`dataset/bench_multi.py`（单轮、多数据集、抽样、并发、max_tokens、duration）。
- 采集：`ep_lab/run_multi_ep_cell.sh`（tokens/s、e2e、TTFT、TPOT、专家热度、rank 负载、npu-smi、服务端日志、rebalance 时序）。

现有缺口：没有 EvalScope、没有 vllm、没有 PD 分离部署、没有 MTP、没有显式的前缀缓存压测、没有多轮对话、没有随机长度 prompt 生成器。

## 1. 逐条评估与转移方案

### 测试1：EvalScope 多轮（5 轮、16K 输入、MTP、前缀缓存）

- 参考：单机 8×H200（NVIDIA），EvalScope 构造 5 轮对话，16 请求 / 并发 16，长上下文 + 高 MTP 接受率 + 高前缀缓存命中率。
- 参考成绩：Output Throughput 678.74 → 916.59 tok/s（+35%），平均 TPOT 18.14 → 13.16 ms。
- 评估：部分可转移。workload 可以复刻，但工具不同，且参考硬件是 H200；我们的 910C 数值只能作为自己的基线，不能和 H200 直接比。
- 需要新增：
  - 安装 evalscope（ModelScope 的评测压测工具）；
  - SGLang 启动加 `--enable-prefix-caching`；
  - 验证 MTP 投机解码在 910C + SGLang 上是否可用。
- 脚本形态：`evalscope perf --url http://<sglang>:30000 --model glm-5.2 ...`，workload 参数照抄固定测试。

### 测试2：SGLang + GLM-5.2 W8A8 + TP32 + 短输出 + 并发 128（最推荐）

- 参考：4 机 32 张 910B2，TP32；输出 16 token；并发 128 时约 325 decode tokens/s（约 10.16 tok/s/卡）。
- 评估：基本能直接转移，只需改三处：
  - TP=EP=32；
  - max_tokens=16；
  - concurrency=128。
- 拓扑注意：对方是 4 机 × 8 卡 = 32；我们现脚本 EP_SIZE=32 是 2 机 × 16 卡 = 32。两种都能跑，若要完全对齐 4 机可加一个 NNODES=4、每机 8 rank 的启动模式。
- 命令形态：
  - `EP_SIZE=32 bash start_ep64_decode.sh`（现脚本：2 机 × 16）
  - `DURATION=1800 CONCURRENCY=128 MAX_TOKENS=16 bash ep_lab/run_multi_ep_cell.sh`
- 注意：对方是 910B2，我们是 910C，绝对数字不可直接比，但方法完全一致，适合作为我们集群的固定基准。

### 测试3：随机数据（21K 输入 / 1K 输出 / 单请求）

- 参考：vllm bench serve 随机数据，random-input-len 21403，random-output-len 1024，num-prompts 1，max-concurrency 1。
- 评估：负载可复刻，但工具是 vllm。我们用 SGLang 做等效测试。
- 需要新增：一个随机长 prompt 单请求脚本（生成 21403 token 的随机文本，max_tokens=1024，并发 1）。
- 脚本形态：新增 `dataset/bench_single_long.py`，或给 `bench_multi.py` 加 random 模式。
- 这是单请求长 prefill 场景，补一个 prefill 维度。

### 测试4：PD 分离 + 64K/128K 长上下文 + 前缀缓存 90% + 并发 10/20/30（工作量大）

- 参考：4 节点 A3（每节点 8×910C），GLM-5.1 W8A8，PD 分离（2 prefill + 2 decode），UCM 前缀缓存，TPOT ≤ 30ms，输入 64K/128K，输出 1K，前缀缓存命中率 90%，并发 10/20/30，请求数 = 并发 × 4。
- 评估：最难转移。我们现在是统一服务（非 PD 分离），且没有前缀缓存专项压测和 UCM。
- 需要新增：
  - PD 分离部署（2 prefill + 2 decode，`--deepep-mode normal` / `low_latency`）；
  - 构造并发一半的相似前缀请求；
  - 前缀缓存命中率 90% 的请求集；
  - 64K/128K 长输入 prompt。
- 这属于独立的大任务，不适合改参数就跑。

## 2. 推荐执行顺序

1. 先跑测试2（改动最小，最快出对标数据）。
2. 再跑测试3（新增随机长 prompt 单请求脚本）。
3. 测试1（装 evalscope + 开 prefix caching + 验证 MTP）。
4. 测试4（最后，需要先搭 PD 分离部署）。

## 3. 本次要落地的脚本改动清单

| 项 | 改动 |
|---|---|
| 测试2 | start 脚本支持 EP_SIZE=32；run 脚本传 CONCURRENCY=128、MAX_TOKENS=16 |
| 测试3 | 新增 dataset/bench_single_long.py |
| 测试1 | 安装 evalscope；SGLang 加 --enable-prefix-caching；验证 MTP |
| 测试4 | 新增 PD 分离启动脚本 + 前缀缓存压测脚本（后置） |
