# 最小场景跑通 + 三件事验证（2026-10-12，单机 node23）

**目标**：只验证"跑通"和三个待定问题，**不做性能实测**。
**最小场景**：真实文本 1 条请求，**64 输入 / 32 输出**（`datasets/min_real_64_32.json`）。
**服务**：单机 16 卡，TP16/EP16，MTP = NEXTN（steps=3 / topk=1 / draft=4）。

## 2. 三件事的答案

### ① MTP × 低延迟 DeepEP × Decode Graph —— **三者无法共存**

- **MTP 与 `deepep auto`（decode 走 low-latency）在所有镜像上都崩**：
  v0.5.16 → `MoeLowLatencyDispatch/CombineV2 do tiling failed`；v0.5.20 → `log_inner.cpp ReportCallError`。
  （graph 开、关都崩，说明是**低延迟内核本身**与 MTP 的 draft/verify 路径不兼容。）
- **MTP 只能在 `--deepep-mode normal` 下跑**；而 normal 模式下三个镜像都打印：
  ```
  Cuda graph is disabled because deepep_mode=`normal`
  ```
  → **传 graph 参数也没用，decode graph 不会启用**（v0.5.16/0.5.19/0.5.20 一致）。
- **含义**：MTP 拿不到"低延迟 DeepEP + Decode Graph"这条快速 decode 路径（榜单 baseline 是有的）。
  → MTP 的收益**只能做同配置 ON/OFF 相对比较**；绝对值和榜单比必须注明这一点。

### ② KV 池容量 —— **可以把 mem-fraction 提到 0.92，池子近翻倍；v0.5.19 最大**

| 镜像 | mem 0.88 | mem **0.92** |
|---|---|---|
| v0.5.16 | 29568 | **55296** |
| v0.5.19 | — | **70912** ← 最大 |
| v0.5.20 | — | 59904 |

- 32K 输入 + 300 输出（33068 token）在 mem 0.92 下**放得下**（之前 mem 0.88 时被拒收）。
- **100K 前缀仍然放不下**（最大 70912）→ 用例 1 需要 HiCache / KV offload / 更多卡，或把用例降到 ~64K 以内。

### ③ 最小场景跑通 —— **AL = 2.133，正好接近文档目标 2.0(±5%)**

- 5 个工作配置（C/D/E/F/G）的最小探针结果**完全一致**：AL **2.133**、接受率 **0.400**、TTFT 3.2~3.4s、E2E ~9.5s。
- 说明：**短场景下 MTP 行为正常且可复现**；之前 1K/1024 输出看到的 AL 3.1~3.3 是**长输出/长上下文**造成的偏高。

## 3. 建议的正式配置（MTP 实验）

```
镜像:   v0.5.19（KV 池最大 70912；若要求与榜单同镜像则用 v0.5.16）
MTP:    --speculative-algorithm NEXTN --speculative-draft-model-quantization unquant
        --speculative-num-steps 3 --speculative-eagle-topk 1 --speculative-num-draft-tokens 4
并行:   --tp-size 16 --ep-size 16（单机 16 卡）
DeepEP: --moe-a2a-backend deepep --deepep-mode normal      ← 只能 normal
Graph:  传不传都一样（normal 下被禁用）
显存:   --mem-fraction-static 0.92                          ← KV 池 55296~70912
其他:   --context-length 131072 --chunked-prefill-size 16384 --max-prefill-tokens 65536
        --disable-shared-experts-fusion --max-running-requests 4
        （不要挂 v0.5.16 的 loader 补丁到新镜像上）
```
