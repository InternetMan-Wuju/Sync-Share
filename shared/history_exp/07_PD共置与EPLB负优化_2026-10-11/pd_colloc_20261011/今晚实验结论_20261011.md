## 3. 卡住的部分 ❌ 及根因

### 现象
第 2 次（乃至空转下的第 1 次）调 `POST /dump_expert_distribution_record` 之后，
**服务被打死**：64 个 rank 全部停止推进 → `Health check failed ... detokenizer` → 进程被 watchdog SIGKILL（exit 137，其余 rank exit 3）。

### 根因（已定位，有完整堆栈）
```
Scheduler hit an exception: ... dump_record() → _accumulator.dump() → _dump_to_file() → torch.save()
RuntimeError: ... current working operator name is HcclAllreduce
[ERROR] Invalid_Argument(EI0005): The arguments for collective communication are inconsistent
        between ranks, ccl_op HcomAllReduce
```

**是我的补丁引入的 bug**：我加的"去掉环形 buffer 里未填满的零行"是**按 rank 各自裁剪**的，
于是各 rank 传给 `all_reduce` 的张量**形状不同** → HCCL 判定"集合通信参数不一致" → abort。

> ⚠️ 坑中坑：错误堆栈停在 `torch.save → storage.cpu()`，看起来像"保存文件出错"，
> 实际是 **HCCL 异步报错**在 `torch.save` 触发的设备→主机拷贝时才浮出来。
> 排查时不要被这个堆栈误导（要看 `ASCEND_LAUNCH_BLOCKING=1` 或往上找 ccl 报错）。

### 修复（已完成，未验证）
集合通信**必须用完整 buffer**（环形 buffer 天然每 rank 都是 `buffer_size` 行 → 形状一致）；
**只在 rank0 写文件时**才裁零行。已改并重新生成补丁（语法通过）。
